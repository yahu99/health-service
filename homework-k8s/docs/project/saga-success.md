# Успешное оформление заказа — последовательная Saga

![Успешное оформление заказа — последовательная Saga](./saga-success.png)

## Что показывает схема

- Создание заказа не блокирует клиента до завершения всей Saga: API возвращает
  `202 Accepted` и идентификатор заказа.
- Фоновый Saga Worker внутри Order Service последовательно вызывает Billing,
  Warehouse и Delivery.
- Следующий шаг начинается только после ответа `SUCCEEDED` от предыдущего.
- После успешного выполнения всех шагов заказ получает статус `CONFIRMED`.
- Итоговый статус клиент получает отдельным запросом `GET /orders/{orderId}`.

NGINX Ingress и внутренние операции сервисов со своими таблицами PostgreSQL
здесь не детализированы: они уже показаны на общей контейнерной диаграмме.
